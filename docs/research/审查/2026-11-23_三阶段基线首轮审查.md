# 三阶段解析基线首轮结果审查

审查日期：2026-11-23  
被审文件：`docs/research/阶段汇报/阶段汇报_三阶段基线_2026-11-23.md`  
核验对象：`outputs/staged_baseline_20261123_233712.csv`（30 回合，seed 42）、`demos/08_staged_baseline.py` 当前修复版、FORGE 上游源码与相关原始论文。

## 审查结论

首轮试验真实地得到 **6/30 成功（20.0%）**，相对两个 0% pilot 是重要的阶段性进展；但该结果仅来自单一随机种子序列，且 95% Wilson 区间约为 **9.5%–37.3%**，不可称为正式性能结论。

汇报中关于阶段 C 和负 `F_z` 的关键分析与逐步 CSV 不符，必须更正。下一轮可以运行“纯 A+B、600 步”的诊断性试验，但不得将 C 判定为“纯螺旋、导纳未生效”或据此得出 C 恶化成功率；也不得以“纯 A+B 达到 30%”作为直接启动残差 PPO 的唯一门槛。

## 可确认的事实

下列项目均由逐步 CSV 重算确认：

| 项目 | 复核结果 |
|---|---:|
| 成功 / FORCE_ABORT / TIMEOUT | 6 / 8 / 16 |
| 成功首次步数 | 232、263、275、380、386、392；均值 321.3 |
| 进入 B | 26/30 |
| 进入 C | 7/26（以进入 B 的回合为分母） |
| 各回合最大力的均值 | 3.895 N |
| 成功回合经过 C | 0/6 |

因此，三阶段结构至少证明“安全高度横向对中 + 条件下降”可以在当前随机序列中产生非零成功，值得继续推进。平均峰值力相对于两个早期 pilot 较低是描述性事实，但不是公平的安全性比较：三组的回合长度、终止时刻、随机序列和接触覆盖比例不同，不能直接宣称“力降低 57%”。

成功回合的最终 `z_cmd` 为 **-2.763、2.091、2.984、3.084、5.211、6.376 mm**；汇报中“2.1–6.4 mm”遗漏了 EP00 的 -2.763 mm，应修正。

## 阻塞性事实错误

### 1. 阶段 C 的导纳并非全程为零

汇报称“全部 C 回合的 `adm_x/y` 均为 0”“实际运行的是纯螺旋”。CSV 与此不符：

| C 阶段指标 | 复核结果 |
|---|---:|
| C 阶段总控制步 | 639 |
| `adm_x` 或 `adm_y` 非零的步数 | **251** |
| 有非零导纳偏置的 C 回合 | EP01、EP03、EP05、EP07 |
| 导纳偏置范数最大值 | **7.071 mm** |

例如 EP01 的 step 282 已记录 `adm_x=-0.316 mm`、`adm_y=-0.632 mm`；之后偏置继续累积。故“导纳自然未生效、没有方向风险”的说法错误：本轮已实际使用 `c_sign=+1` 的未验证方向，必须把该方向视为**未验证且可能影响 C 失败**，而不是视为已排除的风险。

### 2. `c_max_offset=5 mm` 的实现不是 5 mm 向量限幅

脚本使用逐分量 `torch.clamp(offset, -0.005, 0.005)`；当两个分量都到边界时，偏置范数为 `sqrt(2) × 5 = 7.071 mm`。再叠加最大 2.5 mm 的螺旋目标，最终横向目标可远大于“毫米级近孔微调”的设计口径。

在下一次启用 C 前必须：

1. 按 L2 范数裁剪 `admittance_offset`，而不是逐轴裁剪；
2. 单独记录、限幅最终 `spiral + admittance` 目标；
3. 以小规模、固定初态的正负 `c_sign` 对照验证方向，再进行 C 消融。

### 3. 负 `F_z` 的“100% 在 B”是记录逻辑造成的，不是数据结论

首轮 CSV 中原始 `F_z<0` 样本共有 **4118** 个，按记录阶段为 A: 2435、B: 1568、C: 115；最小值为 -0.2326 N。汇报中的 1803 是旧脚本只在 B 阶段累加的 `neg_fz_events`，因此“1803 个负 F_z 事件 100% 在 B”不能用于说明物理现象。

不过所有样本都高于 -0.5 N，故将 `F_z < -0.5 N` 作为“显著负向异常”阈值是合理的日志降噪规则。它只改变**计数口径**，不是下一轮控制性能改善；下一轮不能把“负 F_z 事件减少”列为算法效果指标。

## 回合分类与失效机理的修正

### 阶段 B 卡滞的回合归类不一致

EP04、EP14、EP17、EP29 在全程 400 步均处于 A，未进入 B；因此它们不能出现在“12 个 B 阶段 TIMEOUT 的 gate 违规”分析中。EP07、EP18、EP21 的后段已进入 C，也不应把“末 50 步”无条件归因于 B 的 `descend_gate`。

可保留的结论是：A 阶段对中慢、收敛后横向漂移、400 步预算不足均为真实瓶颈；但要证明某一 TIMEOUT 是 gate 导致，须按**实际 `phase` 分段**统计 B 内的 `xy > descend_gate` 步数和对应 `z_cmd` 停滞，而不是按整回合末 50 步统计。

### FORCE_ABORT 漏洞的判断成立，但需要复跑验证修复效果

旧版本将 `xy > descend_gate` 放在限力回退判断之前，确会使 gate 外步跳过回退逻辑；当前版本已把 `F_z >= backoff_ratio × threshold` 移至无条件优先判断，这是正确修复。8 次中止中 EP02、EP27、EP28 的终态 xy 分别约为 4.94、6.71、6.37 mm，也与 gate 外受力风险一致。

但“漏洞解释全部 8 次中止”尚未通过消融验证。下一轮保持其他参数、只改变该逻辑，才能报告修复前后的中止率差异。

## 对下一轮 A+B 与 PPO 方向的裁定

### 允许的下一轮

允许先运行 C 关闭、600 步的 A+B 诊断。它回答的是“无 C 时，限力逻辑修复和时间预算增加能否改善成功/中止/超时构成”，不是正式最终指标。

该轮必须保存：完整 CLI 参数、脚本 SHA-256、Isaac Lab commit/version、逐步 CSV；并从日志按实际阶段给出 A→B、首次接触、预警、回退、成功、中止的转移计数。修改代码后再运行而无版本快照，将不能严谨归因。

调参建议按单因素顺序进行：先固定 A/B 参数复跑验证限力修复；再单独改变 `max_steps`；最后才调整 `xy_tol`、`hold_steps` 或 `descend_gate`。禁止一次同时改变 gate、A 判据、时间预算和 C，否则结果不可解释。

### 不批准的 PPO 门槛

“A+B 成功率达到 30% 即启动 PPO”的数字没有数据或文献依据。残差 RL 的核心要求不是任意成功率门槛，而是**最终控制动作确为已验证基座与学习残差的叠加**。残差学习文献将经典反馈控制解决的部分与学习到的残差控制信号相加；基座的实现与评估必须一致。[Residual Reinforcement Learning for Robot Control](https://arxiv.org/abs/1812.03201)

当前 `forge_ext/base_policy.py` 仍是旧的“同步下降 + 2 mm 螺旋”策略，与有效的阶段 A+B 控制器不是同一基座。因此，进入 PPO 前的必要条件为：

1. 将冻结、验证后的 A+B 策略实现为残差环境实际调用的 base policy；
2. 在残差环境中运行零残差评估，并与独立 A+B 脚本在相同种子、相同回合数下比较成功率、峰值力和阶段轨迹；
3. 之后才允许二维残差 PPO 冒烟训练。

## 与公开方法和 FORGE 的一致性判断

当前 A→B→C 的高层分解是合理的：公开 peg-in-hole 工作通常将粗对准、接触搜索和柔顺/阻抗插入分开；螺旋搜索是在受控接触/阻抗条件下使用，而非用于替代大范围自由空间对中。[Triyonoputro et al., 2019](https://arxiv.org/abs/1902.09157) [NIST 的搜索策略比较](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=922206)

但 FORGE 的贡献是使用力观测、力阈值和动力学随机化训练策略来适应接触，而不是证明某个固定参数的螺旋/导纳必然有效。因此，20% 的解析基线应作为“结构化先验可行”的证据；后续的合理研究问题是：在同一力阈值随机化与相同初始误差下，残差策略能否减少 A/B 的漂移、缩短时长并降低安全中止率。[FORGE 原论文](https://arxiv.org/abs/2408.04587)

## 汇报的最低修订项

1. 删除或改写“C 为纯螺旋、导纳全程为零、自然满足方向验证、C 恶化总体成功率”；
2. 修正成功回合 `z_cmd` 范围；
3. 将负 `F_z` 的统计改为“旧 B 内计数口径”，并明确 -0.5 N 阈值只改变异常定义；
4. 按真实阶段重做 TIMEOUT 分析，移除从未进入 B 的回合；
5. 将 20% 标为单种子、30 回合的首轮估计，补充不确定性；
6. 将 PPO 前门槛改为“冻结 A+B 基座并在残差环境零残差复现”，而不是任意 30% 成功率。
