# gate 对照失效与配对性修复审查

> 2026-11-24 再审勘误：历史 CSV 的外层窗口跨越 FORGE 自动复位，涉及单回合成功率、耗时、漂移和 gate 重跑顺序的原裁定已修订。见[回合边界勘误](2026-11-24_gate对照再审与回合边界勘误.md)。

审查日期：2026-11-24  
被审文件：`docs/research/阶段汇报/阶段汇报_gate对照失效与配对性修复_2026-11-24.md`  
核验对象：3 mm-A/B、4 mm 的 CSV / JSON 快照，`demos/08_staged_baseline.py`，`tools/compare_runs.py`，以及 Isaac Lab / FORGE 本地源码。

## 审查结论

“3 mm vs 4 mm 旧对照不能归因于 gate”的结论**成立**。两组均为 SHA `3b808a6d…`、CLI 仅 gate 不同，但逐回合首条记录只有 EP00 一致，EP01–EP29 已不是同一初态样本。因此 36.7% 对 26.7% 只能作为非配对 pilot；汇报给出的 Fisher p≈0.580 与“不作参数优劣结论”的口径正确。

逐回合重播种是正确的工程修复方向，且新的 `z_min` 硬裁剪、C 最终目标限幅前记录、下降许可字段均是有效改进；但**新配对机制尚无运行数据验证**。在把下一轮称作“配对单因素 gate 对照”之前，必须先完成同配置的确定性双重复验证，并将配对检查升级为严格初态/随机化状态检查。

## 已复核事实

### 旧对照确实失配

| 对照 | 首步观测一致回合 | 结论 |
|---|---:|---|
| 3 mm-A（旧）vs 3 mm-B（`z_min` 修复） | 30/30 | 修复在本随机流上行为保持；EP26 的 `z_cmd` 仅由 -8.319 改为 -8.000 mm，结局不变 |
| 3 mm-B vs 4 mm | 1/30（仅 EP00） | 非配对，不能将结果差异归因于 gate |

3 mm-B 的 11/30、9 ABORT、10 TIMEOUT，与汇报相符；4 mm 的 8/30、12 ABORT、10 TIMEOUT，也与汇报相符。逐回合转移表合计 23/30 个结局变化，属于不同初态样本下的正常现象，不能作为 gate 效应。

### 随机流分叉机制判断正确，但说明不完整

FORGE 的 interval 死区随机化确会消耗 `torch.rand`，回合长度变化会影响后续 reset 时的随机流位置。除此以外，FORGE 每个物理更新还会为末端位姿、姿态和力观测生成随机噪声；reset 时也会随机化初态、EMA、控制增益、力阈值与死区。因此“间隔死区事件”不是唯一原因，完整表述应为：

> 同一全局随机流同时服务于逐步观测噪声、interval 事件与 reset 随机化；一旦某回合的步数或控制分支不同，后续 reset 使用的随机流位置改变，后续回合初态不再可配对。

这不影响“旧对照失配”的结论，但能避免论文/答辩中被指出机制解释不完整。

## 仍未通过的配对性保证

### 1. 新重播种尚未实证

当前代码在每回合 `reset()` 前执行 `unwrapped.seed(seed * 1000 + ep)`；Isaac Lab 的该静态方法会重设 Torch 与相关全局随机源，作为单环境串行实验的候选方案是合理的。

但该事实不能替代实验验证。物理仿真、全局随机源、reset 路径和 GPU 操作是否在不同进程间完全确定，必须由运行结果证明。

在 3 mm / 4 mm 对照之前，必须先用**完全相同的命令**连续独立运行两次（建议 10 回合即可），并验证：

1. 每个回合 `ep_seed` 相同；
2. reset 后的初态、力阈值、EMA 因子、控制增益与死区阈值相同；
3. 同参数下每回合终局、步数、逐步动作/观测（允许明确声明的浮点舍入容差）相同。

若该自一致性试验失败，不能使用当前 `unwrapped.seed()` 方案做配对统计，应改为显式保存并回放每回合的随机化参数/初态。

### 2. 当前 compare 工具的“初态”不是 reset 初态

`compare_runs.py` 将 CSV 第 0 行的 `obs_x/y/z` 作为初态，但脚本是在执行一次 `env.step(action)` **之后**才写第 0 行。它是“第一步动作后的带噪观测”，并非 reset 时的真实状态。

对于本次旧 3/4 mm 对照，这一代理已经足以发现 29 个回合不一致；但对未来要证明“配对成功”的实验不够严格。应在 reset 后、第一步动作前独立写入每回合元数据，至少包括：

- `ep_seed`；
- 初始观测、初始动作；
- `force_threshold`、EMA 系数、任务空间增益、位置阈值、死区阈值；
- 用于成功判据的真实 held/fixed 相对位姿（仅用于审计，不进入策略观测）。

`compare_runs.py` 应优先比较这些 reset 元数据。现有 `--tol=1e-3 m`（1 mm）也过松，应使用 CSV 精度可支持的 `1e-6 m`，或对记录的随机化参数采用精确比较。

## 对下一步判定规则的修正

“4 mm 的配对 McNemar p<0.05 才继续；未显著即冻结基线”不宜作为唯一规则。30 个配对的统计功效有限，未显著不等于证实固定参数没有余量；反之，单 seed 的显著结果也不是正式泛化结论。

推荐两层决策：

1. **pilot 配对层**：同一 30 个已验证配对初态上，看方向、效果量、ABORT 安全性与 McNemar 结果，决定是否值得进入正式验证；
2. **正式冻结层**：选择一个配置后，在至少 3 个独立 seed 家族、每个 30 回合下评估；只在此层报告成功率均值/区间，并作为残差基座冻结版本。

## 批准的严格实验顺序

1. 运行 3 mm 同配置双重复，先验证新重播种的确定性；
2. 记录 reset 元数据并加强比较工具；
3. 在同一脚本 SHA、同一 `ep_seed` 方案下运行配对 3 mm 与 4 mm；
4. 工具必须先输出“所有 reset 元数据一致”，才允许输出 McNemar 解释；
5. 仅在 pilot 方向与安全性均可接受时，选择配置进入多 seed 正式评估；
6. 正式基线冻结后，将**相同 A+B 逻辑**移植至 `forge_ext/base_policy.py`，完成残差环境零残差等价验证，再启动 PPO。

## 汇报修改建议

- 保留“旧 gate 对照失效、需重跑”的核心结论；
- 将随机流机制说明扩展为“观测噪声 + interval 事件 + reset 随机化的共同消耗”；
- 将“修复”改称“待验证的配对机制实现”，直到同配置双重复通过；
- 明确 CSV 首行是第一步后观测，不能称为严格 reset 初态；
- 不将 3 mm-A/B 的行为保持性推广到其他配置；其成立原因是该特定随机流与结局恰好未因硬裁剪发生额外步数/随机消耗差异。
