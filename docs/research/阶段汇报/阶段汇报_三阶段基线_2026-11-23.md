## 三、逐项分析

### 3.1 负 F_z 的统计口径澄清（按审查修正）

首轮汇总打印的"1803 次"是**旧脚本仅在 B 阶段累加的计数器**，不是全部负值样本。对原始 CSV 的完整统计：

| 统计项 | 数值 |
|---|---|
| F_z<0 的原始步数（全阶段） | **4118（A 2435、B 1568、C 115）** |
| 最小值 | −0.23 N |
| 是否存在低于 −0.5 N 的样本 | 无 |

结论：所有负值均为力平滑滤波的微小负偏（量级 ≤0.23 N），不是物理接触事件。脚本修复将异常计数门槛设为 `F_z < −0.5 N`（`--neg_fz_alert`）。**注意：该阈值只改变异常定义（日志降噪），不代表下一轮控制性能改善；下一轮不得把"负 Fz 事件减少"列为算法效果指标。**

### 3.2 TIMEOUT 按实际 phase 分段分析（按审查要求重做）

对 16 个 TIMEOUT 回合按 CSV 的 `phase` 字段分段统计（替换此前不严谨的"末 50 步"口径）：

| 卡点 | 回合 | 分段证据 |
|---|---|---|
| **A 阶段未收敛**（4 回合） | EP04、14、17、29 | 全程 A（400 步），A 段内 xy>3 mm 占 289–342 步——对中本身未达标 |
| **B 段 gate 暂停主导**（8 回合） | EP06、10、13、15、19、22、25、26 | 纯 B 段内 xy>gate 占比 56–91%（EP15: 309/338、EP22: 319/366、EP06: 197/228）；z_cmd 大幅停滞（EP15 停在 56.7 mm、EP22 停在 38.7 mm） |
| **时间预算不足叠加** | EP13、25 | A 段耗 270/297 步，B 段下降正常启动但回合用尽（EP13 末态 z_cmd 8.4 mm，接近插入深度） |
| **末段在 C 的回合**（4 回合） | EP01、07、18、21 | B 段 gate 违规同样高（EP07: 36/69、EP18: 164/191）；C 段 z_cmd 设计上不动（停滞为预期），不计入 gate 卡滞 |

与阶段 A 数据（收敛后漂移 2.96–9.12 mm）一致：3 mm 的 descend_gate 与漂移量级相当，导致 B 段大量"下降—暂停"切换。EP13 类回合说明 400 步预算对"A 慢 + B 受 gate 调制"的组合不够。

### 3.3 FORCE_ABORT 的机理：限力逻辑存在 gate 依赖漏洞

8 次 ABORT 中，EP02 中止时 xy=4.94 mm、EP27/28 时 xy=6.71/6.37 mm——**均在 3 mm gate 之外**。检查代码逻辑发现：原实现中 `xy > gate` 时跳过整个限力块，导致销钉在孔内被横向漂移挤压时 F_z 无约束增长直至冲破阈值。

**这解释了为什么预警阈值（0.55×阈值）没有防住中止**：预警本身生效，但 gate 外的步完全不受限力保护。

### 3.4 阶段 C：0/7 成功、3 次中止；导纳方向未验证且已实际参与（按审查修正）

| 事实 | 证据 |
|---|---|
| 进入 C 的 7 回合 0 成功、3 次 FORCE_ABORT | EP03、05、20 在 C 中中止 |
| **导纳并非全程为零**（修正此前错误表述） | C 阶段 639 个控制步中 **251 步 `adm_x/y` 非零**，涉及 EP01、03、05、07，偏置范数最大 **7.071 mm** |

**两项重要更正**：

1. 此前汇报称"导纳全程为零、实际运行纯螺旋"是**事实错误**（成因：分析脚本只统计了成功回合的导纳计数，而成功回合均未进入 C，却被推广到全部 C 回合）。实际运行中 `c_sign=+1` 的未验证方向**已参与控制**——C 的失败与该方向是否正确**可能相关**，不能视为已排除的风险；
2. 旧实现用**逐分量 clamp** 限幅导纳偏置（±5 mm），两分量同时到界时偏置范数达 √2×5=7.07 mm，叠加最大 2.5 mm 螺旋后最终横向目标可达 7.5 mm 以上——远超"毫米级近孔微调"的设计口径。已修复：偏置改为 **L2 范数限幅**，最终目标（base+admittance）单独按 L2 限幅（`--c_max_total`，默认 4 mm）并记录限幅前后的量。

**当前对 C 的严谨结论**：在本轮设置下 C 未能产生成功且伴随中止风险；由于方向未验证、限幅实现有缺陷，C 失败的原因无法归因（方向错误 / 目标过大 / 螺旋本身无效均有可能）。C 暂停启用，待限幅修复后以正负 `c_sign` 小规模固定初态对照验证方向，再做独立消融。

另注：本节及全篇不再使用"C 恶化成功率"的表述——7 回合样本且与 A/B 段状态混杂，不足以支撑该因果判断。

## 四、已完成的修复（对应 §3 各发现）

`demos/08_staged_baseline.py` 已更新（语法检查通过）：

1. **限力无条件生效**（§3.3 漏洞）：`F_z ≥ backoff_ratio×阈值` 时回退 z_cmd（clamp 至复位高度），不再受 gate 约束；gate 仅控制下降许可。**该修复的效果尚未经消融验证**——首轮 8 次中止中 EP02/27/28 的终态 xy 与 gate 外受力风险一致，但"漏洞解释全部 8 次中止"须在下一轮（其他参数不变、仅改该逻辑）中对比中止率才能确认；
2. **负 F_z 按量级计数**：`--neg_fz_alert`（默认 −0.5 N），口径变更见 §3.1；
3. **阶段 C 默认禁用**：`--c_enable`（默认关闭）；
4. **导纳偏置 L2 限幅 + 最终目标 L2 限幅**（§3.4 修复）：偏置范数上限 `--c_max_offset`（5 mm），最终横向目标上限 `--c_max_total`（4 mm），替代旧的逐分量 clamp；
5. **回退上限 clamp**：`z_cmd` 回退不超过复位高度；
6. **时间预算**：`max_steps` 默认 400 → 600；
7. **版本快照**（审查准入要求）：每次运行自动打印并写入 `*_config.json`——CLI 参数全量、脚本 SHA-256[:16]、Isaac Lab 版本。此后任何代码修改再运行都有快照可归因。

## 五、下一轮计划（按审查裁定）

1. **允许的下一轮**：C 关闭、600 步的 **A+B 诊断性试验**（30 回合，seed 42 连续序列）。它回答"无 C 时，限力逻辑修复和时间预算增加能否改善成功/中止/超时构成"，**不是正式最终指标**。运行记录要求：`*_config.json` 自动快照（CLI、脚本 SHA、Isaac Lab 版本）+ 逐步 CSV + 按实际 phase 的 A→B、首次接触、预警、回退、成功、中止转移计数；
2. **单因素调参顺序**（审查要求，禁止同时改多项）：先固定 A/B 参数复跑验证限力修复效果 → 再单独改 `max_steps` → 最后才动 `xy_tol`/`hold_steps`/`descend_gate`；
3. **进入 PPO 的前置条件（按审查裁定，替代此前的"30% 成功率"门槛）**：残差学习的前提是**最终控制动作确为已验证基座与学习残差的叠加**。因此必须：
   - 将冻结、验证后的 A+B 策略实现为残差环境实际调用的 base policy（当前 `forge_ext/base_policy.py` 仍是旧的"同步下降 + 2 mm 螺旋"策略，与有效的 A+B 控制器不是同一基座）；
   - 在残差环境中做**零残差评估**，与独立 A+B 脚本在相同种子、相同回合数下比较成功率、峰值力和阶段轨迹；
   - 通过后才允许二维残差 PPO 冒烟训练；
4. C 阶段方向验证（独立小规模试验）：固定初态、正负 `c_sign` 对照、限幅修复后的实现——通过后再做 C 消融；
5. **后续研究问题的表述**（按审查）：FORGE 的贡献是用力观测、力阈值与动力学随机化训练策略适应接触，而非证明固定参数螺旋/导纳必然有效。本课题 20% 的解析基线应作为"结构化先验可行"的证据；合理的研究问题是：**在同一力阈值随机化与相同初始误差下，残差策略能否减少 A/B 段的漂移、缩短时长并降低安全中止率**。
