## 二、对照失效：同种子 ≠ 同初态

### 2.1 配对性检查结果

逐回合比对两轮 CSV 的首步观测（初始位姿）：

| 检查项 | 结果 |
|---|---|
| 共同回合数 | 30 |
| 初态一致回合 | **1（仅 EP00）** |
| 初态不一致回合 | **29** |

EP00 是进程启动后的第一次 reset，两轮消耗的随机数序列相同，因此一致；其后的每个回合都不同。

### 2.2 逐回合命运翻转

| 转移（3 mm-B → 4 mm） | 回合数 |
|---|---|
| OK → ABORT | 7 |
| ABORT → TIMEOUT | 5 |
| TIMEOUT → OK | 4 |
| TIMEOUT → ABORT | 3 |
| TIMEOUT → TIMEOUT | 3 |
| OK → OK | 2 |
| ABORT → ABORT | 2 |
| ABORT → OK | 2 |
| OK → TIMEOUT | 2 |
| **合计变化** | **23/30** |

仅一个 gate 参数改动导致 23/30 回合改变结局——这一比例本身即是"比较对象不是一个东西"的强烈信号，而非参数效应的体现。

### 2.3 统计后果

两轮实为**两组不同的初始条件样本**（各 n=30），只能做非配对比较：

- 非配对 Fisher 精确检验：11/30 vs 8/30，**p ≈ 0.58**；
- 即便差异真实存在，n=30 的非配对设计也无法检出该量级的差异。

**结论：36.7% vs 26.7% 的差异不可归因于 `descend_gate`；本轮 gate 对照失败，需重跑。**

## 三、机理核实（源码级）

不是实现 bug，是 Isaac Lab + FORGE 的随机数消耗模型导致：

1. `direct_rl_env.py:385-386`：每步调用 `self.event_manager.apply(mode="interval", dt=self.step_dt)`；
2. FORGE 的死区事件 `randomize_dead_zone` 注册为 `mode="interval"`, `interval_range_s=(2.0, 2.0)`，每次触发消耗 `torch.rand`；
3. `_reset_idx` 中的 `randomize_initial_state` 同样从 `torch.rand` 采样初始位姿、孔位、摩擦、增益；
4. **回合长度不同 → 重置前累计消耗的随机数个数不同 → 下一回合采样到不同的初始条件。**

即：`--seed` 只固定随机流的起点，不固定"每个回合从流的哪个位置开始采样"。只有第 0 回合可复现。

## 五、修复

### 5.1 逐回合重播种（默认开启）

`demos/08_staged_baseline.py`：每回合 `env.reset()` 前调用

```python
unwrapped.seed(seed * 1000 + ep)
```

- 使"同回合号"在不同配置下获得**相同的初始位姿**，以及**相同的死区分段序列**（死区事件按仿真时间触发，与回合长度解耦后即可对齐）；
- CSV 新增 `ep_seed` 字段，可逐行核验；
- `--no_reseed` 复现旧行为（用于对照或复现历史数据）；
- 新脚本 SHA-256[:16] = `a7a8256955bfbac5`。

### 5.2 配对比较工具

`tools/compare_runs.py`：

1. 读取两轮 config 快照，打印 SHA/种子/回合数；
2. **配对性检查**：逐回合比对首态，不一致即明确警告"本比较不是配对比较"并列出受影响回合；
3. 汇总指标 + Wilson 区间；
4. 逐回合命运表与变化回合清单；
5. 配对时给 McNemar 精确检验，非配对时给 Fisher 精确检验。

实测输出（本轮两轮）：

```text
配对性检查：共同回合 30，初态不一致 29
  ⚠ 本轮比较不是配对比较——跨轮差异混入了初始条件差异。
非配对 Fisher 精确检验（11/30 vs 8/30）：p≈0.580
```

## 六、附带发现：`z_min` 修复的行为等价性验证

3 mm-A（旧 SHA `f7ed0487`，`z_min` 修复前）与 3 mm-B（新 SHA `3b808a6d`，修复后）**未加逐回合重播种**，但两轮：

- 初始条件 **30/30 完全一致**；
- 逐回合末态与结局一致；
- **唯一差异：EP26 末态 `z_cmd` 由 −8.319 mm 变为 −8.000 mm**（该回合仍为 SUCCESS）。

即：EP26 之外，`z_min` 硬裁剪没有改变任何行为；修复是安全的、行为保持的。两轮 3 mm 数据因此**互为配对**，也说明旧版 36.7% 在新脚本下可精确复现。

> 注意：一旦启用逐回合重播种（`a7a82569`），随机流被重新定义，**新的 3 mm 与 4 mm 都必须重跑**，不能与上述三份历史数据配对。
